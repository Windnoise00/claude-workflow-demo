Ask before any change to systems or config, and explain each change simply.

**Why:** the user is responsible for these systems and wants to understand and own every change.

**How to apply:**
- Read-only checks, dry runs and status commands need no approval.
- Propose as a numbered list: what, why, what could go wrong, how to undo. Wait for a yes per item.
- "Do it" covers what was discussed, nothing wider. See [[feedback-verify-live]].
